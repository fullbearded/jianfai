# 3.4 多 Agent 系统设计

> 本系列：《WorkBuddy 从入门到放弃》 · 第三章 精通 · 预计阅读 14 分钟

## 这一篇解决什么问题

看完这篇，你能把一项复杂任务设计成一支分工明确的数字员工团队。

## 本篇要点

- 多 Agent 的前提是单 Agent 已经跑通
- 分工按真实岗位来设，不是越多越强
- 明确每个 Agent 的输入、输出和交付标准
- 系统设计的目标是稳定交付，不是炫技

## 内容大纲（待撰写）

- 什么时候该上多 Agent：任务跨度大、角色分明
- 角色设计：职责、边界、交接物
- 协作方式：串行、并行、评审
- 验收：整体交付质量如何把关
- 反模式：为了多 Agent 而多 Agent

## 按标准验收

- [ ] 你设计了一个最小的多 Agent 系统
- [ ] 该系统能稳定产出一份完整交付物

## 沉淀可复用资产

做完这篇，你应该沉淀出：一张多 Agent 系统的角色与交接图。
